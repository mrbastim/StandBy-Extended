# Проверка AMOLED Protection 2.0

[English](testing.md) | [Русский](testing.ru.md)

## Тестовый стек и границы проверок

Приложение использует Kotlin 2.0.21, Compose, AGP 8.5.2, Gradle 8.7, JDK 17,
compile/target SDK 35, minSdk 28. До изменения были только JUnit 4.13.2 тесты чистой
логики; DI, мокинг, UI-, screenshot- и end-to-end harness отсутствовали.

Сохранён JUnit4; добавлен только Robolectric 4.14.1 для окон, SensorManager и lifecycle
на API 28 и 35. Эта версия совместима с текущим стеком; зависимости production,
AGP и версия приложения не обновлялись. Масштабная миграция на Hilt и новые системы
скриншотных тестов не нужна для изолированной экранной политики.

- DisplayProtectionPolicyTest / AmbientLightFilterTest: обычные JVM-тесты фаз,
  таймеров, диапазонов, смены настроек, восстановления после касаний, быстрых lux,
  гистерезиса, отсутствия датчика и независимости сессий.
- DisplayProtectionAndroidTest: симуляция Window и корутин с Android main looper,
  восстановление атрибутов, промежуточные значения яркости, новая Activity-сессия,
  повторный запуск контроллера и события lifecycle DreamService.
- AmbientLightAndroidTest: отсутствие датчика, отказ регистрации, идемпотентность
  подписок, отключение режима и освобождение listener при остановке.
- DisplayProtectionSettingsAndroidTest: сохранение всех параметров через DataStore,
  нормализация некорректных значений и сохранность остальных настроек.

Симуляция нового окна не заменяет реальное пересоздание Compose Activity. Тест lifecycle
DreamService не поднимает системную dream-сессию через DreamManager. Эти интеграции
и физическая яркость проверяются отдельно на устройстве.

## Регрессионная проверка запуска release

CI подписывает неподписанный minified release временным тестовым ключом и дважды запускает
MainActivity на эмуляторе API 28 до изолированной job релизной подписи. Завершение процесса
или фатальная ошибка AndroidRuntime прерывают проверку. Тот же workflow выполняется для PR.
Так проверяется регрессия моста lifecycle после R8; это не заменяет проверки яркости
на устройстве или установки APK с производственным сертификатом.

Установите подписанный APK, скачанный из GitHub prerelease, запустите MainActivity
и убедитесь, что приложение продолжает работать без `LocalLifecycleOwner not present`
в logcat. Повторите холодный запуск и откройте настройки. Запуск debug и успешная
сборка R8 сами по себе не проверяют этот мост reflection. Release и prerelease
подписываются одним релизным ключом; установленный локально debug APK обычно имеет
другой сертификат и не обновляется опубликованным APK без миграции установки.

## Автоматические команды

Из корня репозитория:

```shell
./gradlew --console=plain testDebugUnitTest lintDebug assembleDebug
./gradlew --console=plain assembleRelease
```

Первая загрузка Robolectric может потребовать скачать Android runtime для API 28/35.
Отчёт тестов: app/build/reports/tests/testDebugUnitTest/index.html.
Lint: app/build/reports/lint-results-debug.html.
APK: app/build/outputs/apk/debug/app-debug.apk.
Release-сборка дополнительно проверяет R8/resource shrinking; публикация не выполняется.

Только чистая логика защиты:

```shell
./gradlew testDebugUnitTest --tests '*DisplayProtectionPolicyTest' --tests '*AmbientLightFilterTest'
```

## Ручная матрица Android

Проверить API 28 и современную версию Android, устройство без TYPE_LIGHT,
телефон с OLED/AMOLED и хотя бы одну OEM-прошивку с поддержкой DreamService.
Для первого прохода использовать короткую задержку 10–20 секунд, затем вернуть
120 секунд и 12 секунд перехода. Проверки ниже являются инструкциями, а не
утверждением об уже выполненном тестировании физической панели.

1. Системная яркость: записать текущее значение, включить StandBy с 35%, перейти
   к 8% после бездействия. Выйти из preview, свернуть приложение, открыть системные
   настройки и другое приложение. Глобальная настройка яркости не должна меняться.
2. Переход: коснуться экрана в начале, середине и конце затемнения; сделать
   быстрые повторные касания, свайп и долгое нажатие. Должен быть один плавный
   возврат; через новый полный период бездействия затемнение повторяется.
3. Источники данных: оставить часы/музыку/погоду обновляться без касаний.
   Переход в Ambient должен произойти по таймеру, секунды и плавный ход исчезают,
   будильник показывает часы/минуты. В освещённом помещении выбранная тема должна
   сохраняться. Тап возвращает обычную частоту обновлений.
4. Освещение: включить адаптацию, медленно изменить свет, затем кратко закрыть
   датчик рукой. Отдельный краткий всплеск не должен давать скачок. Длительное
   затемнение комнаты снижает активную яркость в заданном диапазоне. В Ambient
   яркий свет не отменяет минимум. В почти полной темноте (после фильтра ≤1 lux в течение
   10 секунд) ночная палитра включается только после достижения заданного минимума яркости.
   В просто тусклой комнате выше этого порога бездействие не должно включать ночную палитру.
   Возврат света (после фильтра ≥3 lux в течение 5 секунд) возвращает дневную палитру даже
   при сохранении минимума яркости по бездействию. Повторить без датчика и с отключённой
   адаптацией: автоматического перехода в ночь нет. Проверить ручной Night Mode.
5. Отсутствие датчика: убедиться в подсказке и ручной яркости. Выключение адаптации,
   уход в фон и остановка заставки должны освобождать TYPE_LIGHT listener
   (можно проверять через Android Studio Profiler / dumpsys sensorservice).
6. Тайм-ауты: проверить Keep Awake on/off × Follow system/1 min/5 min/Never,
   затем дополнительный таймер 15 min. Keep Awake имеет приоритет над обычным
   Timeout; дополнительный таймер явно отменяет удержание. После отпускания
   Activity ждёт системный тайм-аут, а заставка завершается.
7. Пересоздание Activity: включить системное «Не сохранять действия», повернуть
   устройство, сменить язык/размер окна, закрыть/открыть приложение. Новое окно
   начинает Active, настройки сохранены; зарядка и ориентация продолжают обновляться.
   Проверить блокировку/разблокировку, Home/возврат и физическую кнопку питания.
8. DreamService: выбрать заставку в системных настройках и запустить на зарядке.
   Проверить минимум/касания, остановить/запустить дважды, затем отключить зарядку.
   После завершения нет оставшихся подписок и принудительной яркости другого окна.
   Отдельно проверить предпросмотр и настоящий запуск по системному тайм-ауту.
9. Pixel Shifting: пройти четыре страницы и музыкальный виджет в обоих стеках,
   подождать не менее пяти минут на каждой группе размеров/плотностей.
   Контент перемещается без обрезания, касания совпадают с положением элементов.
   Проверить маленький landscape-экран, вырезы, крупный шрифт, редакторы и отключение.
10. Сохранение: изменить каждый параметр, завершить процесс и открыть приложение;
    значения должны сохраниться. Protection off возвращает системную яркость;
    отдельные Pixel Shifting и Keep Awake продолжают работать.
11. Локализация и доступность: открыть раздел на русском, английском и турецком,
    проверить TalkBack для переключателей и слайдеров, управление клавиатурой,
    отсутствие обрезанных значений при крупном шрифте.

Не проводить проверку выгорания намеренным длительным отображением высокой яркости.
Наблюдение за изменением яркости и корректностью жизненного цикла не является
доказательством предотвращения выгорания.
